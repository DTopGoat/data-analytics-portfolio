Clinical trials analytics in dbt

A tested star schema for 4,288 completed cancer trials: staging, intermediate and mart layers, 48 data tests, CI on every push.

Code on GitHub [REPO_URL] Repository link coming soon.

The question

A research-operations team wants to benchmark completed oncology trials: size, duration, sponsors, locations and how reliably results get posted. The API returns nested JSON with partial dates, free-text conditions, duplicate site rows and inconsistent sponsor names, so analysts were re-cleaning the same data in spreadsheets for every question.

What I did

A small Python script pulls a reproducible slice from the API into raw CSVs. dbt on DuckDB models it as sources, staging, intermediate and marts, using the same conventions I use on Snowflake. The marts are a fact table of studies, dimensions for sponsors, conditions and sites, and bridge tables, exported to CSV and Parquet for BI tools.

Testing

15 models and 48 tests, all passing: unique and not-null keys, relationships from every fact and bridge to its dimensions, accepted values on status and phase, and singular tests. For example, a study’s completion date can never fall before its start, and site counts on the fact table must reconcile exactly with the site bridge. SQL is linted with sqlfluff and GitHub Actions runs the build on every push and pull request.

Cleaning rules

Month-only dates resolve to the first of the month. Combined phases normalize to Phase 1/2 and 2/3. Conditions are grouped case-insensitively. Duplicate site rows are dropped. When a sponsor appears with more than one class, the most frequent class wins.

What it shows

  • 4,288 completed cancer trials enrolled 784,777 participants. The median trial enrolled 53 people.
  • 34.1% posted results. Industry sponsors post results about twice as often as academic centers (52.6% vs 26.0%).
  • Phase 3 trials have a median enrollment of 300 and a median duration of 58.4 months.
  • Breast cancer is the most common condition (330 studies).

Tools
