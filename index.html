How it works

  1. Open-Meteo APIsHourly weather and air quality, 6 cities
  2. Python ingestRetries with backoff, hourly
  3. BronzeRaw rows, append-only, DuckDB
  4. Silverdbt incremental, latest record per city and hour
  5. GoldHourly fact, daily rollup, AQI and heat index bands
  6. Tests39 dbt tests, freshness, reconciliation
  7. PublishJSON on GitHub Pages, read by Thy Weather and this page
Bronze, Silver, Gold
Bronze keeps every raw API row with its load time and is never updated. Silver types and deduplicates it. Gold holds the tables the app reads.
Incremental with lookback
Each run re-sends the same hours as forecasts change. Silver reads only rows loaded since its last run minus a 3-hour lookback, then keeps the latest record per city and hour. It’s the same pattern I used to fix a dbt incremental key that was dropping ~97% of expected records at work.
Tests and data quality
Unique keys, not-null, accepted values and range checks, source freshness, and a Bronze-to-Gold row-count reconciliation. Results are stored every run.
Orchestration
GitHub Actions runs ingest, dbt build, freshness, export and publish at 17 minutes past every hour. A failed run opens a GitHub issue and closes it on recovery.
CI
Every pull request runs pytest, sqlfluff and a full dbt build on fresh data.
